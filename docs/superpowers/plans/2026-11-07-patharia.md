# Patharia Hills and Tea-Garden Biome Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Patharia Hills (Sylhet, ≈ 234 m) as a playable mountain. It uses a new `tea-garden` biome:
- contour-striped tea slopes
- tea hedge rows near the player
- sparse shade trees
- forest on steep tilas

**Architecture:**
- **Bake:** gains a `summitName` option.
- **Palettes:** gain optional contour `stripes`.
- **Vegetation:** a biome's single `trees` config becomes a list of `vegetation` layers.
  - `trees` layers use the existing `TreeSystem` (now with `minSlopeDeg` and a variant subset).
  - `tea` layers use a new pure `placeTea` and an instanced `TeaSystem` over 64 m cells near the player.
- **Data:** the mountain itself is data: bake config, `patharia.json`, and a catalog entry.

**Tech Stack:** TypeScript 5.9, Three.js, React 19 HUD, Vitest (Node), Playwright, Python 3 + numpy/rasterio.

**Spec:** `docs/superpowers/specs/2026-11-07-patharia-design.md`.

## Global Constraints

- Work on branch `patharia`, created from `main`.
- `src/engine/**` never imports React. Every gameplay or tuning number lives in `GAME_CONFIG`. Visual mesh shape constants live in the system file, as in `TreeSystem.ts`.
- **Mera and Keokradong must not change.**
  - `himalaya` has no vegetation.
  - `tropical-hills` has exactly one `trees` layer, with today's values: seed 986, spacing 7, density 0.35, maxSlope 40, route clearance 4, camp clearance 20, ring radius 1, scale 0.8–1.4, `castShadow` false.
  - Its palette has no stripes.
  - Bake defaults are unchanged (`summitName` defaults to "Summit").
- Biomes change only looks. Gameplay rules stay global.
- No vegetation colliders. Nothing is placed within route clearance (4 m) or camp clearance (20 m).
- `routeMaxSlopeDeg` is never above 33. The exact attribution is `Contains modified Copernicus DEM data`. Nothing under `public/terrain/` is committed.
- Use `.venv/bin/python` for Python. The npm `terrain:*` scripts call the system `python3`, which lacks rasterio on this machine.
- Run `npm run format` before every commit. CI runs `format:check`, `lint`, `typecheck`, `test`, `build` and `e2e`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Deliberate deviation from the spec

The relief map (`mapImage.ts`) uses the palette **without** stripes. The map samples every 64 m, while stripes repeat every 0.8 m of height, so they would alias into noise. Task 2 records this in spec §3.

How the test values are derived:
- **Slopes.** A grade of 0.15 is about 8.5°, which is inside 3–20°. A grade of 0.02 is about 1.1°, so it is too flat. A grade of 0.6 is about 31°, so it is too steep.
- **Rows along x.** On the 0.15 plane, height depends only on z. So for a given z, every x from 0 to 63 is either kept or not, which gives rows of 64 along x.
- **Yaw.** The normal has no x component, so the contour runs along ±x and `|cos(yaw)|` is 1.

- [ ] **Step 3: Implement `src/engine/world/teaPlacement.ts`**

```ts
import type { TreeAvoid } from './treePlacement';

type P3 = readonly [number, number, number];

export interface TeaRules {
  /** Grid step of candidate points (m). */
  stepM: number;
  minSlopeDeg: number;
  maxSlopeDeg: number;
  /** Height between neighbouring rows (m). */
  riseM: number;
  /** Fraction of each rise that holds a row (0–1). */
  bandFraction: number;
  routeClearanceM: number;
  campClearanceM: number;
}

export interface TeaGround {
  heightAt(x: number, z: number): number | null;
  slopeDegAt(x: number, z: number): number | null;
  normalAt(x: number, z: number): { x: number; y: number; z: number } | null;
}

export interface TeaInstance {
  x: number;
  y: number;
  z: number;
  /** Rotation about +Y that aligns the hedge's local +X with the contour. */
  yaw: number;
}

function segmentDistSq(px: number, pz: number, a: P3, b: P3): number {
  const dx = b[0] - a[0];
  const dz = b[2] - a[2];
  const len = dx * dx + dz * dz;
  const t = len === 0 ? 0 : Math.max(0, Math.min(1, ((px - a[0]) * dx + (pz - a[2]) * dz) / len));
  const x = a[0] + t * dx - px;
  const z = a[2] + t * dz - pz;
  return x * x + z * z;
}

/**
 * Tea hedges on contour bands of gentle slopes (Patharia spec §4): a world-aligned grid
 * point is kept when its height falls in the lower `bandFraction` of each `riseM`.
 */
export function placeTea(
  area: { minX: number; minZ: number; maxX: number; maxZ: number },
  ground: TeaGround,
  rules: TeaRules,
  avoid: TreeAvoid,
): TeaInstance[] {
  const s = rules.stepM;
  const pad = Math.max(rules.routeClearanceM, rules.campClearanceM);
  const nearArea = (p: P3) =>
    p[0] > area.minX - pad &&
    p[0] < area.maxX + pad &&
    p[2] > area.minZ - pad &&
    p[2] < area.maxZ + pad;
  const segments: [P3, P3][] = [];
  for (const route of avoid.routes) {
    for (let k = 0; k + 1 < route.length; k++) {
      if (nearArea(route[k]) || nearArea(route[k + 1])) segments.push([route[k], route[k + 1]]);
    }
  }
  const camps = avoid.camps.filter(nearArea);
  const routeSq = rules.routeClearanceM ** 2;
  const campSq = rules.campClearanceM ** 2;

  const out: TeaInstance[] = [];
  for (let i = Math.ceil(area.minX / s); i * s < area.maxX; i++) {
    for (let j = Math.ceil(area.minZ / s); j * s < area.maxZ; j++) {
      const x = i * s;
      const z = j * s;
      const slope = ground.slopeDegAt(x, z);
      if (slope === null || slope < rules.minSlopeDeg || slope > rules.maxSlopeDeg) continue;
      const y = ground.heightAt(x, z);
      if (y === null) continue;
      const band = y / rules.riseM - Math.floor(y / rules.riseM);
      if (band >= rules.bandFraction) continue;
      if (camps.some((c) => (c[0] - x) ** 2 + (c[2] - z) ** 2 < campSq)) continue;
      if (segments.some(([a, b]) => segmentDistSq(x, z, a, b) < routeSq)) continue;
      const n = ground.normalAt(x, z);
      if (!n) continue;
      // Contour direction is perpendicular to the horizontal normal: d = (-n.z, n.x).
      // Local +X rotated by yaw is (cos yaw, -sin yaw) in (x, z), so yaw = atan2(-d.z, d.x).
      out.push({ x, y, z, yaw: Math.atan2(-n.x, -n.z) });
    }
  }
  return out;
}
```

Check the yaw formula against the test. The plane's normal is `(0, ·, −g)`, so `d = (g, 0)` along +x, and `yaw = atan2(0, g) = 0`, which gives `cos = 1`. ✓

The segment distance helper duplicates the one in `treePlacement.ts`. Export it from `treePlacement.ts` as `segmentDistSq` and import it here instead of copying. That is cleaner and avoids verbatim duplication.

**Behaviour:**
- **Visual constants** at the top of the file:
  - `HEDGE = { length: 1.8, width: 0.9, height: 0.8 }`
  - `TOP_COLOR = 0x4f8f2e`, `SIDE_COLOR = 0x2f5e1f`

- **Avoid data** comes from `manifest.routes` points and `manifest.camps` positions, as in `TreeSystem`.
- **Cells.** They are world-aligned squares of `cellSizeM`, keyed `` `${ci}_${cj}` `` with `ci = floor(x / cellSizeM)`.
- **`update(x, z)`:**
  - The wanted cells are those whose centre is within `radiusM` of (x, z), clamped to the baked area: the manifest origin plus tiles × tile size.
  - Remove cells that are not wanted: remove the mesh from its parent and call `mesh.dispose()`.
  - Then build up to `maxCellsPerUpdate` missing wanted cells, nearest centre first.
  - For each, call `placeTea(cellArea, ground, rules, avoid)`. If it returns no instances, record the cell as built with no mesh, so it is not retried every frame.
  - Otherwise create an `InstancedMesh(geometry, material, count)`. Set each matrix from position (x, y, z) and Y-rotation `yaw`, with scale 1. Set `castShadow` from the rules and `receiveShadow` false, call `computeBoundingSphere()`, and add the mesh to the parent.
- **`cellCount`** is the number of built cells, including empty ones.
- **`dispose()`** removes and disposes all meshes, then the geometry and the material.
